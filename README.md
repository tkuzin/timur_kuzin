# Служба поддержки timur_kuzin

Учебный сервис Кузина Тимура Денисовича, вариант 2. Принимает заявки, хранит переписку, проводит заявку по статусам и сравнивает время первого ответа сотрудника с нормативом категории. Сводка показывает открытые заявки и нарушения срока реакции по всем данным.

## Требования

Проверенный стенд: Windows 11, Python 3.14.1, PostgreSQL 18.4. FastAPI 0.143.0, SQLAlchemy 2.1.4, psycopg 3.3.6, Uvicorn 0.54.0, Jinja2 3.1.6. Все зависимости зафиксированы в `requirements.lock.txt`. Docker не требуется.

Проект развёртывания, база данных и схема имеют имя `timur_kuzin`. В PostgreSQL используются только индексы первичных ключей. Прикладного кеширования, очередей и фоновых задач нет. Содержимое заявок и комментариев хранится в БД; исходный код, шаблоны интерфейса и результаты экспериментов — в репозитории.

## Установка и запуск в Windows

Откройте PowerShell в корневой папке проекта. Установите Python 3.14 и PostgreSQL 18, если их ещё нет. Для локального экземпляра нужен свободный порт 55432, для приложения — 8080. Скрипт не изменяет существующие службы PostgreSQL.

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
powershell -ExecutionPolicy Bypass -File scripts\setup_local.ps1
.\.venv\Scripts\python.exe -m scripts.seed small
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8080 --no-access-log
```

Последнюю команду оставьте работающей в терминале. Интерфейс: http://127.0.0.1:8080. Автоматический контракт OpenAPI: http://127.0.0.1:8080/docs. Сотрудник: `operator`, клиент: `client`, демонстрационный пароль для обоих: `timur-demo-2026` (или значение `DEMO_PASSWORD` на момент наполнения).

Если PostgreSQL установлен по другому пути, перед запуском setup задайте:

```powershell
$env:PG_BIN = 'D:\PostgreSQL\18\bin'
```

Скрипт создаёт `.env` со случайными секретами и отдельный кластер `.local/pgdata`. Повторный запуск подключает существующий кластер. Каталог `.local` и `.env` исключены из Git. Папка проекта находится в OneDrive: при дальнейшем использовании рекомендуется перенести проект вместе с остановленным кластером в обычную локальную папку, чтобы файлы работающей БД не синхронизировались.

Для отдельной уже настроенной БД вместо `setup_local.ps1` скопируйте `.env.example` в `.env`, заполните подключение и секрет, затем выполните `python -m scripts.init_db` из окружения. Учётной записи нужны права создать базу (если она отсутствует), схему и таблицы.

## Повторный запуск и остановка

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_local.ps1
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8080 --no-access-log
```

Приложение в терминале останавливается `Ctrl+C`. Для скрытого запуска служит `scripts/start.ps1`; PID и журналы записываются в `.local`. Не запускайте второй экземпляр на занятом порту.

После остановки приложения локальную БД можно остановить командой:

```powershell
& 'C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe' stop -D '.local\pgdata' -m fast
```

## Проверка сценариев

1. Войти как `client`, создать заявку, открыть её и добавить уточнение.
2. Выйти, войти как `operator`, найти заявку фильтром, взять в работу и ответить. В карточке появится срок реакции.
3. Закрыть заявку; новый комментарий к закрытой заявке отклоняется.
4. Открыть «Сводку». Норматив считается нарушенным при ответе строго позже срока либо при истечении срока без ответа. Доля нарушений считается от всех заявок категории, включая закрытые; открытые — статусы `new` и `in_progress`.

Клиент видит только свои заявки. Сотрудник видит все заявки и сводку, меняет статусы. Регистрация пользователей в задании не требуется: учётные записи создаёт генератор.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

11 проверок бизнес-правил не обращаются к БД. 17 проверок API используют TestClient и реальный PostgreSQL, без запущенного веб-сервера. База и схема должны быть созданы предыдущими командами; записи для тестов готовятся автоматически и откатываются транзакцией. Последовательности PostgreSQL не откатываются, поэтому перед измерениями обязательно заново выполните seed. Итог прогона хранится в `artifacts/tests.txt`. Предупреждение Starlette о будущем переходе с httpx на httpx2 не влияет на результат текущей зафиксированной версии.

## Данные и измерения

**Seed очищает только четыре таблицы схемы timur_kuzin**, включая заявки, созданные вручную. Перед повторным наполнением сохраните нужные демонстрационные данные отдельно. Генератор использует фиксированные формулы и даты, повторный запуск одного объёма даёт одинаковые строки и идентификаторы.

| Таблица | Малый набор | Рабочий набор |
|---|---:|---:|
| users | 50 | 3 000 |
| categories | 5 | 10 |
| tickets | 300 | 50 000 |
| comments | 900 | 150 000 |

При работающем сервере выполните последовательно, без параллельных тестов и ручных действий в интерфейсе:

```powershell
.\.venv\Scripts\python.exe -m scripts.seed small
.\.venv\Scripts\python.exe -m scripts.benchmark small
.\.venv\Scripts\python.exe -m scripts.seed work
.\.venv\Scripts\python.exe -m scripts.benchmark work
```

Каждый сценарий: 5 прогревочных запросов, затем 30 учитываемых, один клиент, без конкурентной нагрузки, учётная запись `operator`. p50 — медиана; p95 — элемент с номером ceil(0.95 × N) отсортированной серии. Замер HTTP включает получение всего ответа. Подготовка для смены статуса и повторный вход перед logout выполняются вне таймера. Чтения предшествуют сериям записи. С учётом прогрева серия добавляет 71 заявку и 35 комментариев; итоговые количества сохраняются.

В `artifacts/samples_*.csv` находятся сырые наблюдения, в `benchmark_*.json` — сводные показатели, в `seed_*.json` — реальные количества из БД и SHA-256 входных строк генератора. Заголовки `X-SQL-Ms`, `X-SQL-Queries`, `X-App-Ms` показывают время вызовов драйвера, число SQL-команд и время обработки сервером. SQL-время включает обмен с локальным PostgreSQL и работу драйвера; это оценка затрат обращений к БД, а не чистое процессорное время PostgreSQL. Остаток HTTP − SQL включает Python, преобразование данных, сериализацию, транзакционные накладные расходы и локальную HTTP-передачу. Поэтому его нельзя называть чистым CPU-временем Python.

Счётчик `X-SQL-Queries` учитывает прикладные SQL-команды через SQLAlchemy. Служебная проверка соединения пулом и команды управления транзакциями отдельно не учитываются; их расходы входят в остаток HTTP − SQL.

## Отчёт

`artifacts/ДЗ1_Кузин_Тимур.docx` содержит 13 страниц, автоматическое оглавление, две иллюстрации, результаты и гипотезы. Перед сдачей нужно заполнить учебную группу и URL опубликованного репозитория. Скрипты build_report.py / render_word.ps1 / preserve_report.py относятся к подготовке отчёта, требуют исходного DOCX-шаблона и среды работы с документами; для запуска сервиса они не нужны.

## Программный интерфейс

Полный контракт с полями, правами и ошибками: [docs/API.md](docs/API.md). Машиночитаемая схема доступна по `/openapi.json` и сохранена в `artifacts/openapi.json`.

## Структура

- `app/` — модели, бизнес-правила, API и HTML-интерфейс.
- `scripts/` — локальный PostgreSQL, создание схемы, генератор, замеры.
- `tests/` — бизнес-правила и API.
- `artifacts/` — результаты испытаний, скриншоты и материалы отчёта.

Исходные результаты ДЗ 1 следует сохранить перед изменениями для следующих этапов. Гипотезы об оптимизации сейчас не реализованы.
